**Lattice** is the design system shared across our product teams. It exists so
that a button, a form field, or a color choice means the same thing everywhere —
and so teams spend their time on product problems, not on re-deciding spacing.

The docs are organized in three layers, each building on the one below it.

## Foundations

The shared vocabulary every component draws from.

- [**Color**](/foundations/color/) — the token palette and why we use OKLCH.
- [**Typography**](/foundations/typography/) — the type scale, families, and
  line-height rules.

## Components

Reusable building blocks composed from the foundations.

- [**Button**](/components/button/) — variants, states, and when to use each.
- [**Input**](/components/input/) — labelled text fields with helper and error
  states.

## Patterns

How components combine to solve a recurring problem.

- [**Forms**](/patterns/forms/) — laying out, validating, and saving a form
  using [buttons](/components/button/) and [inputs](/components/input/).

## How to read these docs

Start at the [foundations](/foundations/color/) if you're theming or building a
new component. If you're assembling a screen, start at the
[patterns](/patterns/forms/) and follow the links down to the components they
use.
